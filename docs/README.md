## 1. 板块定位与命名（章程）

- ERP 是**板块**，不是第六条产品线。它位于「一十百千万」ladder 之外，与营销/客服台板块同级（先例见 `openspec/specs/crm-board/spec.md`）。
- 板块名 **ERP**，**双语同形**：EN=ERP / 中文=ERP。板块标签 **「板块 / Board」**。
- 官网板块位：tab 用非 ladder 线标「账」，带板块标签，链接到板块落地页 `/erp`（中文 `/zh/erp`）；不使用 `products/<line>` 路由。
- **五线不变**：`PRODUCT_LINES` / `LADDER_CHARS` / `LADDER_NUMERALS` 是公共契约（`fd-official-web/src/content.config.ts`），ERP MUST NOT 成为第六线；五线命名与 slug 一律不改。本 change 未改动 `content.config.ts`。

## 2. 组合形态

- ERP 以 **「集群 + 供给包」组合** 交付：账本内核 pack + 行业舰队 + 连接器 pack + 报表 preset；**不是单体 ERP 应用 / 表单式 UI**。
- 行业差异全部上移为行业模板资产（连接器 pack + 舰队蓝图 + 科目映射 + 报表 preset），账本内核保持行业无关。
- 账本内核可如实陈述的真实能力：复式事件账；agent 拟稿经确认门才成为事实；外部系统事实经导入车道按来源权威直接成为事实；两者都按人工确认的过账规则派生分录，缺规则即挂待补、不猜科目；借贷必平由数据库约束强制；已落账分录 append-only；余额由分录确定性重算、不设直写余额字段；`stable_id` 幂等去重；多币种原币 + 本位币折算（汇率 + `as_of` + 出处，无出处汇率拒绝）；对账引擎只读滩头、四类差异含双侧原始引用、对外部系统零写入；租户列隔离 + 查询闸。

### 2.1 子模块全覆盖四态（矩阵派生，勿手改）

「全覆盖」指**决策空间**全覆盖：ERP 子模块全集里每一格都恰好一态、一据、一理由，使对外回答只出现四种答案，不存在没有判据的「暂未支持」。它并不表示内核里逐个实现了这些模块——形态仍是「集群 + 供给包」。

本节由 `fd-erp/shared/coverage-matrix.json` 生成（`scripts/claim_gate.py render`），判据是 `fd-erp/tools/check_coverage_matrix.py`；块外再手写一份四态表会被声明门判红。

期末现金 − 期初现金」**，不等时报差额与未归类科目、绝不调明细凑平；**补充资料（间接法）**（change: add-cash-flow-indirect）：净利润 + 折旧/减值/汇兑加回 − 营运资本变动（1100/1200/1300/2000/2100），并断言与直接法经营净额相等——两条独立路径对不上就报差额，不给任何一方凑平；已落账调汇分录不计入营运资本变动，避免同一个 200 幂等，第二张会让余额翻倍而它自己是平的）、**仅限空账**（已有分录即拒，事后插入会改写全部历史报表；真需要时须显式 `allow_with_entries` 并给出理由，理由回显留痕）。`preview()` 把已落账期初投影成逐科目余额，账簿期初列必须与它相等。**期间对比已交付**（change: add-report-comparison / add-ytd-comparison）：`comparison` 把三表逐行与基准期间对齐，给出本期 / 基准 / 差额 / 变动率。基准是**封闭集合**（上一期间 / 去年同月 / **本年累计 vs 上年同期累计**，跨年按日历回退，不猜「最近有数的期间」）；累计口径下流量表逐月用同一套单月引擎再累加、现金净增加额按区间两端相减，存量表明确 `notApplicable`（余额是时点数），累计里任一月份不自证就点名 `inconsistentMonths`；**基准为零不给变动率**（除零与写 0% 都是谎，差额照常给）；**没有基准期间不冒充零**（`baselineAvailable=false`，基准值与变动率置空）；差额一律「本期 − 基准」、变动率分母取绝对值（亏损扩大不会被显示成增长）；本期列复用同一报表引擎，MUST NOT 另写一份取数。**账簿已交付**（change: add-ledger-books）：`books` 给出三栏**科目余额表**（期初 / 本期借方 / 本期贷方 / 期末，逐科目 + 合计 + 借贷平衡断言）与**明细账**（逐笔流水带**逐行余额**，「期初 + 借 − 贷 == 期末」自证，行序=业务日期→落账时刻→txn→行号；按行数截断只截显示、合计与期末仍按全量算）。两本账与试算平衡表**同源互证**：科目余额表期末列必须与 `trial_balance` 的余额逐科目相等——三条路径对不上就是有一处算错了，不允许拿任一方遮盖另一方。**期间关账已交付**（change: add-period-close）：分录带独立**业务日期** `booked_on`（与落账时刻 `posted_at` 分开，期间归属因此与会话时区解耦），`accounting_periods` 追加式记录 close/reopen（无可变状态列），**数据库触发器**拒绝业务日期落在已关期间的分录（绕应用层直接 SQL 也进不去），顺序关账（早于目标且未关的期间先拦）、只重开最近一期且须理由，关账写快照（逐科目借/贷/净额/行数 + 借贷合计）并可按快照复算核对（不一致逐科目点名差额）。**期末结转已交付**（change: add-profit-closing）：`closing` 把本期损益逐科目按净额**反方向结平**（收入记借、成本费用记贷），借贷差额计入 `3100 留存收益`（盈利记贷、亏损记借），业务日期取期间末日；结转分录带固定前缀（`source_ref` 以 `close:` 开头），因此**不进利润表与按维度费用表的口径**——否则已结转期间的利润表会显示收入 0、费用 0（那不是这期没赚钱，而是账做完了）；试算平衡表与资产负债表照样包含它，`unclosedProfit` 因此只反映尚未结转的期间。同期间按稳定键 `close:<期间>` 幂等（不重复过账），已关账期间拒绝结转，本期无损益时不生成 0 元分录。工具面（MCP）尚未开这组动作——同其余模板车道，等 REST 面一起接。 **月结清单已交付**（change: add-month-end-checklist / add-profit-closing）：`month_end` 按固定顺序跑「结转出库成本 → 计提折旧 → 计提坏账 → 结转损益」四步，每步只出待确认 proposal，失败即停；期间已关账或期间内有待确认提案时不开跑；**结转损益的基数只认已落账分录**，前序步骤刚出的待确认提案没落账时结转置 `deferred`（少结转一笔费用在报表上看起来完全正常，这才是危险形态）；**关账前置=四步成功且期间内没有任何待确认提案**，关账入口由调用方注入（模板层不实现关账）。`precheck` / `checklist` 只读，逐项给出 `ok|blocker|warning` 与修法。**中国国别包已交付**（change: add-cn-localization-pack）：科目表/税码/报表项目是**数据**（取自 Odoo `l10n_cn` @20.0，出处与 sha256 见 `localization/cn/PROVENANCE.md`，加载期校验，被改过即拒）；增值税用真科目计提（销项 `2221.01.01` / `2221.02`（期间幂等）；按《小企业会计准则》出资产负债表与利润表，报表项目按科目码规则聚合，**落不进任何项目的科目必须点名**（`unmapped`+`complete`）——漏项的报表照样平，所以「平」与「完整」分开报；增值税申报口径与账面逐项勾稽（未提供独立申报数时自报「未核对」）。**不做**：大企业准则的报表格式（科目表已进仓）、附加税/个税、金税与全电发票通道。
- **应收应付** `delivered`——边界：科目级应收应付与余额由分录重算；信用占用从 1300 应收余额派生。**应收账龄已交付**（change: add-receivable-aging）与**应付账龄已交付**（change: add-payable-aging）：两侧**共用同一份** FIFO 核销与分桶实现，只把「开放项方向」参数化（应收借方 / 应付贷方），默认科目 1100 / 2000，分桶 0-30/31-60/61-90/91+，未标维度单列 `unattributed`；多收报 `creditBalance`、多付报 `debitBalance`（都不出负账龄），各桶合计 − 多收/多付必须等于科目净额（`consistent`，不等就如实报不调桶）。口径明说未做逐票匹配。**未做**：坏账计提（需客户政策）与催收流程（需渠道）。 **坏账计提已交付**（change: add-bad-debt-provision）：按账龄分档计提应收减值——口径 `bad_debt_method` 在册（`aging-rate` 已实现，个别认定/直接核销如实 `NOT_WIRED`），分档费率由人工登记（追加式修订，边界递增、率∈[0,1]、末档覆盖无限期，程序不得自设）；计提额 = Σ(账龄桶 × 费率) 与账上 `1231` 比较取**增量**（借 `6602` / 贷 `1231`，减少记反向），业务日期取期间末日、按期间幂等，已确认后改金额报「跨期调整」；报表按净额（`1100 − 1231`）呈现且资产负债表平衡断言继续成立。**往来对账单已交付**（change: add-party-statement）：`books.party_statement(维度键, 维度值, 期间)` 把同一往来方的往来明细**跨科目**串成一条线（应收/收入/回款都在一张单上），逐行给**该科目**的余额（各科目相加恒为零，看往来余额看应收/应付那一行），并给分科目小计与合计。指定 `accounts` 时**对回总账**：本单期末 + 该科目未标该维度的净额 == 总账期末，不等就点名差额、绝不把差额摊给某个往来方；未指定科目时明说未做总账对账。
- **多币种与汇率** `delivered`——边界：分录记原币 + 本位币折算，汇率带 as_of 与出处；无出处汇率由 DB 约束拒绝。汇率事实做种走 fx_facts（可复用既有观测流）。 **期末调汇已交付**（change: add-fx-revaluation）：`fx_revaluation` 按登记好的**期末汇率**把外币**货币性项目**（现金/应收/在途结算款/应付/预收暂收）重述到期末汇率，差额入 `6603 汇兑损益`（期间费用，利润表单列一行）。期末汇率由人工登记且**必须带出处**（同坏账费率：外部事实、程序不得自设，修订留痕）；缺汇率就拒并点名币种，**不回落历史汇率**（那样调汇等于没调）；存货/固定资产/折旧/坏账准备按历史成本或估计计量，**不重述**。判据是差额不是状态：调汇落账后账上本位币已等于外币×期末汇率，重跑差额自然为零，汇率修订后只调新增差额。
- **对账** `delivered`——边界：只读滩头：两源流水逐笔对齐，四类差异（缺失/多余/金额不符/状态不符）各带双侧原始引用，对外部系统零写入。可指向外部两源，也可指向内部「事件流 vs 分录流」。
- **计费** `delivered`——边界：规则版本化 + 人工审批上线 + 冲突拦截 + 事件/期间快照计费（幂等可重算）+ 红冲留痕 + 四层溯源 + 无出处费率拒绝。落账走 billing-engine 机器车道 proposal，不绕过确认门。
- **信用额度** `delivered`——边界：available = limit − 1300 应收余额（分录重算）− active 占用；占用为备忘性质不写复式分录；额度不足带明细拒绝。
- **销售与订单** `template_configured`——边界：订单与销售面在行业模板的页面集与端点里（UE 商城 24/24、SE 业务员台 16/17）；内核只记 order_placed 事件与据此产生的金额事实，不实现行业订单规则。售后申请（退/换/补）由 UE 售后车道受理为**流程记录**，不进事件层——申请不等于退货入库。线索与拜访由 SE CRM 车道受理为**流程记录**（`record=lead/visit`），同样不进事件层：见了一条线索不是拿到一个客户，登记一次拜访不是产生一笔订单。
- **采购** `template_configured`——边界：采购单与到货通知在 SP 供应商面（实现 8/14，其余如实 501）。到货落 goods_received 事件后可投影库存并可过账。
- **库存（数量面）** `delivered`——边界：数量面由事件 + 对象投影回答：数量/单位/批次/序列号/仓库/在途均可表达，余额可全量重算并带水位；REST 面经 `GET /sp/inventory` 只读暴露该余额（按供货范围收口，不是跨供应商全表）。**谁产生这些事实**：入库/出库/调拨/盘点四类作业单由模板层库存作业车道（`inventory.py`）写成拟稿事件（复用 goods_received / goods_issued / goods_adjusted，不新增事件类型），过确认门后投影、再按过账规则落账；出库与调拨先核可用量，不写出负库存。这层的**对外 REST 面尚未接**（需仓库页面集，卡在页面集注册表），当前只能经内核/服务侧调用，页面不可达——不宣称页面可用。上游 WMS 读取仍需一次接入（provider 缺口另记，不在本矩阵）。

## 3. 执行面采纳边界

- 经营动作的执行（发货、支付、补货、开票等）**仅经采纳的外部 MCP server** 完成；平台凭证由租户自带（BYOK）、经环境变量注入，**零落库零日志**。
- 账本内核**只做记录、对账与核对指令层**，不直接驱动任何资金流或对外资金指令。
