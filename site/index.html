ERP 板块：能力、接口与边界

ERP 是「集群 + 供给包」的组合式交付：一个行业无关的复式事件账内核，加行业模板资产（连接器 pack、舰队蓝图、科目映射、报表 preset），经同源入口对外提供 REST 面与 MCP 工具面。它不是单体 ERP 应用，也不提供表单式 UI。

本页所有数字均由 claims.json / gaps.json / tool-surface.json / coverage/ / 模板 manifest 在构建时派生，与 claim_gate 同源；不写价格、客户数、用量或上线日期。

4 · MCP 工具面（21 个）

分组工具读/写行为
proposalsubmit_proposal写write · 只创建 proposals 行、绝不直接落账；同 stable_id 重复提交返回首次结果（唯一索引去重）
proposallist_proposals读read · 分页查询本租户 proposal 列表及状态（待确认/已确认/已拒绝）
proposalconfirm_proposal写write · 确认门；确认后按复式分录落账，借贷必平由 DB 约束强制、不平整笔拒绝；同 stable_id 幂等
proposalreject_proposal写write · 拒绝 proposal，留审计痕迹且不落账；同 stable_id 幂等
ledgerquery_balance读read · 按科目/币种查询余额；余额由 journal_entries 确定性重算，无直写余额字段
ledgerquery_entries读read · 分页查询已落账分录（原币/折算、出处、来源引用、时间戳、冲正关联）
reconrun_reconciliation写long-running · 运行两源流水对账（只读滩头，对外部系统零写入），立即返回 task_id；幂等不产生破坏性副作用，但会创建/推进对账任务与报告状态故非 read-only
reconget_recon_report读read · 按 task_id 查询对账任务状态/进度/结果 + 四类差异清单（缺失/多余/金额不符/状态不符，双侧原始引用）
billingsubmit_billing_rule写write · 登记计费规则新版本（draft→pending_approval）；同 rule_key 版本递增、重复提交产生新版本故非幂等；无出处费率拒绝（RATE_UNSOURCED）
billingapprove_billing_rule写write · 规则确认门（pending_approval→active，人工确认、不接受程序自审自批）；同维度冲突未处置拒绝上线；同 rule_key 旧 active 版本随新版本退役
billinglist_billing_rules读read · 分页查询计费规则（含版本、状态机、config、rate_source）
billingbill_event写write · 按 active 规则对事件计费，写 fee_details（append-only，快照锁定规则版本）+ 组 billing-engine 机器车道分录 proposal（不直接落账）；同 stable_id 重推返回首次结果
billinglist_fees读read · 分页查询费用明细（含红冲反向行 status='reversed' + reversal_of 关联）
billingget_fee_detail读read · 费用详情 + 四层溯源链（费用项→业务单据→作业事件→计费规则版本）+ 快照确定性重算
billingreverse_fee写write · 红冲费用：新增反向明细行（reversal_of 关联，原行原样保留，append-only 无改/删路径）；原分录已落账时组冲正 proposal；同 fee 幂等
billingsimulate_billing读read · 按历史事件集试算新旧规则费用差异（零写入；费率出处纪律同正式规则）
billingbill_period_snapshot写write · 按期间触发日终快照计费（存储费 = 日终库存快照 × 费率）：批量快照 → fee_details（快照锁定规则版本+汇率四要素）+ 一条 billing-engine 机器车道分录 proposal（不直接落账）；幂等键 = (租户, 期间, stable_id)，同期间重跑返回首次结果
creditreserve_credit写write · 占用客户信用额度（备忘性质，不写复式分录）；额度不足拒绝（CREDIT_EXCEEDED 含额度明细）；同 stable_id 幂等返回首次结果
creditrelease_credit写write · 释放信用占用（reserved→released，幂等；备忘表状态推进，非账本事实）
creditquery_credit读read · 查询额度位：limit / ar_balance（1300 分录确定性重算）/ reserved / available
creditlist_credit_reservations读read · 列出信用占用明细（含派生状态 reserved/expired/released 与 expires_at）；不释放、不修改任何占用

9 · 边界

资金（二清红线）

只产出对账结果与核对指令。不提供资金池、代收代付、分账执行；资金归集与分账走客户自选的持牌通道。

开票 / 税务

不自研、当前不提供（挂账）。账内可记录发票类事件并参与对账；票据本体走客户既有合规渠道，不伪造、不代开。

执行面

发货、支付、补货、开票等经营动作仅经采纳的外部 MCP server 完成；凭证由租户自带（BYOK）、经环境变量注入，零落库零日志。

租户隔离

同时服务寻数自用与外部商家/泛企业客户；经营数据按租户隔离，任一客户租户不能读取其他租户的账、单据或报表。
