ERP 板块能力、接口与边界

数据派生勿手改

ERP 是「集群 + 供给包」的组合式交付：一个行业无关的复式事件账内核，加行业模板资产（连接器 pack、舰队蓝图、科目映射、报表 preset），经同源入口对外提供 REST 面与 MCP 工具面。它不是单体 ERP 应用，也不提供表单式 UI。

本页所有数字均由 claims.json / gaps.json / tool-surface.json / coverage/ / 模板 manifest 在构建时派生，与 claim_gate 同源；不写价格、客户数、用量或上线日期。

MCP 工具面（37 个）

proposal

工具读 / 写行为
submit_proposal写write · 只创建 proposals 行、绝不直接落账；同 stable_id 重复提交返回首次结果（唯一索引去重）
list_proposals读read · 分页查询本租户 proposal 列表及状态（待确认/已确认/已拒绝）
confirm_proposal写write · 确认门；确认后按复式分录落账，借贷必平由 DB 约束强制、不平整笔拒绝；同 stable_id 幂等
reject_proposal写write · 拒绝 proposal，留审计痕迹且不落账；同 stable_id 幂等

ledger

工具读 / 写行为
query_balance读read · 按科目/币种查询余额；余额由 journal_entries 确定性重算，无直写余额字段
query_entries读read · 分页查询已落账分录（原币/折算、出处、来源引用、时间戳、冲正关联）

recon

工具读 / 写行为
run_reconciliation写long-running · 运行两源流水对账（只读滩头，对外部系统零写入），立即返回 task_id；幂等不产生破坏性副作用，但会创建/推进对账任务与报告状态故非 read-only
get_recon_report读read · 按 task_id 查询对账任务状态/进度/结果 + 四类差异清单（缺失/多余/金额不符/状态不符，双侧原始引用）

billing

工具读 / 写行为
submit_billing_rule写write · 登记计费规则新版本（draft→pending_approval）；同 rule_key 版本递增、重复提交产生新版本故非幂等；无出处费率拒绝（RATE_UNSOURCED）
approve_billing_rule写write · 规则确认门（pending_approval→active，人工确认、不接受程序自审自批）；同维度冲突未处置拒绝上线；同 rule_key 旧 active 版本随新版本退役
list_billing_rules读read · 分页查询计费规则（含版本、状态机、config、rate_source）
bill_event写write · 按 active 规则对事件计费，写 fee_details（append-only，快照锁定规则版本）+ 组 billing-engine 机器车道分录 proposal（不直接落账）；同 stable_id 重推返回首次结果
list_fees读read · 分页查询费用明细（含红冲反向行 status='reversed' + reversal_of 关联；每行含 refs = 计费时的单据引用，缺失回 {}，供按单据/承运商归集时免 N+1）
get_fee_detail读read · 费用详情 + 四层溯源链（费用项→业务单据→作业事件→计费规则版本）+ 快照确定性重算
reverse_fee写write · 红冲费用：新增反向明细行（reversal_of 关联，原行原样保留，append-only 无改/删路径）；原分录已落账时组冲正 proposal；同 fee 幂等
simulate_billing读read · 按历史事件集试算新旧规则费用差异（零写入；费率出处纪律同正式规则）
bill_period_snapshot写write · 按期间触发日终快照计费（存储费 = 日终库存快照 × 费率）：批量快照 → fee_details（快照锁定规则版本+汇率四要素）+ 一条 billing-engine 机器车道分录 proposal（不直接落账）；幂等键 = (租户, 期间, stable_id)，同期间重跑返回首次结果

credit

工具读 / 写行为
reserve_credit写write · 占用客户信用额度（备忘性质，不写复式分录）；额度不足拒绝（CREDIT_EXCEEDED 含额度明细）；同 stable_id 幂等返回首次结果
release_credit写write · 释放信用占用（reserved→released，幂等；备忘表状态推进，非账本事实）
query_credit读read · 查询额度位：limit / ar_balance（1300 分录确定性重算）/ reserved / available
list_credit_reservations读read · 列出信用占用明细（含派生状态 reserved/expired/released 与 expires_at）；不释放、不修改任何占用

event

工具读 / 写行为
ingest_event写write · 导入车道：写入来自外部系统的原始事实，写入即成为事实（accepted）。同 (租户, 车道, stable_id) 幂等；事件只追加，定型后不可改写，更正只走冲正
submit_event写write · 拟稿车道：agent 产出的事件，落为 pending，未过确认门不算事实（不进对象投影、不过账）；同 stable_id 幂等
decide_event写write · 确认门：把 pending 的拟稿事件置 accepted 或 rejected（唯一改变事件状态的人工入口）；ingest 车道事件不需要确认
query_events读read · 查询事件并返回完整性声明（declared_total/returned/truncated/watermark）；truncated 为真时不得把结果当成全部

object

工具读 / 写行为
query_object_balance读read · 数量面余额（含单位/维度/水位）+ 重算对照；drift 为真表示物化值与事件重算不一致，以事件为准。账本面不提供数量查询
project_event写write · 把已接受事件投影到对象数量面；同 (事件, 对象, 维度) 幂等不叠加。余额是投影产物，不可直写；未过确认门的事件不算事实，不得投影

posting

工具读 / 写行为
submit_posting_rule写write · 提交过账规则草稿（版本化，不参与过账）；科目必须落在机器车道白名单内，且必须同时含借贷两侧
approve_posting_rule写write · 审批上线过账规则：退役旧 active 版本，本版本生效；升版不重写历史分录
list_posting_rules读read · 列过账规则各版本与状态（draft/active/retired）
post_event写write · 按生效规则把已接受事件过一次账；同一事件只过一次。缺规则时抛 POSTING_RULE_MISSING 并把事件挂入待补清单，账本余额不变（不猜科目）
list_posting_gaps读read · 缺规则待补清单：哪些事件在等哪条规则（未解除的缺口）

period

工具读 / 写行为
close_period写write · 关账并写快照；顺序关账（早于该期且有分录的未关期间先拦）、不得关未来期间；同期间重复调用幂等（返回首次结果，不新增记录）
reopen_period写write · 重开最近一个已关期间（须理由）；隔着已关期间重开被拒；追加一条 reopen 记录，不覆盖历史
period_status读read · 期间当前是否关账 + 最近动作（actor/note/时点/快照摘要）
period_report读read · 关账快照 vs 当前复算逐科目核对；不一致返回 verified=false + diffs，不静默报「已关账」
list_periods读read · 列出有记录的期间与当前状态（期间升序）

需一次接入		预算在事件内核下是「预算对象 + 期间投影」，无需新内核能力。引擎已交付（change: add-budget-control-lane）：按口径维度与期间登记预算（人工拍板、修订追加式）→ 承诺占用（`hard-block` 拒 / `warn-only` 放行并标记 / `post-audit` 不拦只记）→ 释放 → 执行查询。承诺由预算车道记（带维度）；**实际开支按维度从内核分录汇总**（change: add-ledger-dimensions：分录自该迁移起带 `dimensions`）——同科目同期**未标注维度**的净额单列为 `unattributedActual`，不被静默漏掉。口径词表（`cost-center`）与内核维度键（`cost_center`）显式映射，不靠字符串巧合对齐。**执行整表已交付**（change: add-budget-execution）：`execution(period)` 把「有预算 / 有承诺 / 有实际」三者取并集出一张表，行是（维度值, 科目）；**双执行率**并列——承诺率回答「额度占了多少」、实际率回答「钱花到哪了」，预算未登记时两者为 null（不写 0%）；`remaining = 预算 − max(承诺, 实际)`（承诺与实际会重叠，取大者作保守估计，不做假去重）；**没登记预算却已花钱的科目点名**（`unbudgeted`）——否则「预算合规」只是没查到的假象；`alerts` 按超支/临近阈值（默认 0.9）点名并标触发口径；累计口径按区间求和（月从 1 月、季从首季），未标维度的实际单列不摊给任何维度，结转分录不计入实际。
需客户提供：引擎已交付（预算控制：三控制方式 + 两种期间粒度 + 四种维度 + 承诺/释放/执行查询 + 按维度实际与未标注单列）；仍缺的只有**数据**：客户预算基数（CSV：dimension_value,account_code,period,baseline_amount）与纳入预算的科目清单。口径已进册且已转 `enforced=true`。**历史分录没有维度**（不回填，猜出来的归属比没有归属更糟），故按维度实际只覆盖维度迁移之后的落账——跨越切换点的期间需人工看 `unattributedActual`。

边界

资金（二清红线）
只产出对账结果与核对指令。不提供资金池、代收代付、分账执行；资金归集与分账走客户自选的持牌通道。
开票 / 税务
不自研、当前不提供（挂账）。账内可记录发票类事件并参与对账；票据本体走客户既有合规渠道，不伪造、不代开。
执行面
发货、支付、补货、开票等经营动作仅经采纳的外部 MCP server 完成；凭证由租户自带（BYOK）、经环境变量注入，零落库零日志。
租户隔离
同时服务寻数自用与外部商家/泛企业客户；经营数据按租户隔离，任一客户租户不能读取其他租户的账、单据或报表。
